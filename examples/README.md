# examples — デグレチェック検証用サンプル

`degrade-guard` スキルを実際に試すためのサンプルソース集です。
いずれも「**変更を1点加えたときに、触っていない既存挙動が不変か**」を机上で検証しやすいよう、
分岐・前提条件を持たせてあります。

## 使い方（検証の流れ）

1. どれか1つのサンプルに、意図した変更を1点だけ加える（例：閾値変更・ランク追加・ルール変更）。
2. その diff を `degrade-guard` に渡し、机上デグレ検証を依頼する。
3. 出力される **机上トレース表**で「影響を受ける集合＝新挙動／補集合＝不変」が正しく示されるかを確認する。

## サンプル一覧

| ディレクトリ | 種別 | 関数の性質 | 想定する変更シナリオ（デグレの起きどころ） |
|---|---|---|---|
| `frontend/` | フロント（TypeScript） | 純粋計算関数 | 送料無料の閾値変更・会員ランク追加 → 既存ランク/金額帯の合計が変わらないか |
| `backend/` | バック（TypeScript） | 状態依存関数（リポジトリ経由） | 集計条件の変更 → 既存の注文状態パターンの集計が変わらないか |
| `iac/` | IaC（Terraform） | 宣言的リソース | SSH 許可元の変更 → 他のイングレス/エグレスが緩まないか |

> これらはあくまで検証用のサンプルであり、本番利用を想定した実装ではありません。
